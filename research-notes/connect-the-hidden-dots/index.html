Research note, October 2026

Connect the Hidden Dots

Connecting pieces of information that do not seem related often leads to surprising and valuable discoveries. Today's agents tend to miss these connections, because their search tools let them find only what they already expect. We use decision models to find the hidden connections in large sets of documents. In our experiments, these connections gave better prediction-market trades, better stock portfolios, faster GPU kernels and new research directions.

Connecting hidden dots leads to great discoveries

Many discoveries started with two known facts that nobody put together before. Each fact was public. Each fact was not important when you read it alone. The discovery was to see that the two facts are related. For example, Wegener found continental drift in a world map and a report about fossils.

In 1910 Alfred Wegener, a German meteorologist, looked at a world map. He saw a shape that a child can see. He thought that the idea was not possible, so he did not use it. One year later, he found a report about fossils by accident. The report had no relation to maps. Together, the map and the report changed geology.

The two pieces were not new. The map was in every atlas. Paleontologists knew about the fossils, and they said that a land bridge connected the continents. Wegener read the two pieces together. He found the second piece by accident.

Find connections everywhere

Hidden connections of this type are not rare. They are in all large sets of documents: news, earnings calls, research papers and personal notes. No single document shows the connection. Thus, nobody searches for it, and nobody uses it.

Below are four connections that our method dug out, from four different fields. Each one joins two ordinary documents that give new information only when you read them together. We describe how the method works in the next sections.

Why today's agents miss it

Today's models can usually see a connection when they have the two pieces, as the examples above show. The problem is how they get the pieces. Agent harnesses give them search tools, such as grep or embedding search. To use these tools, the agent must describe the result that it wants, with words or ideas that the result contains.

Thus, the agent finds only what it can already describe, and the results are rarely a surprise. In practice, agents search around the topic that they already saw, so they look at only a small part of the corpus. Some documents are mostly unrelated, with one small detail that matters and no shared keyword. The agent usually misses them. For example, a search for “Meta capex” finds more about Meta and capital spending. It does not find the PG&E call, which connects only through a chain of reasoning: capital spending, data centers, power, the local utility.

Our experiments show the same problem. We gave agents the same documents and a search tool. The agents did not find the connections that our method found. The kernel section below shows an example.

How our method works

Our method starts from one document. It makes pairs of this document with thousands of other documents. A decision model answers one question about each pair. Then the method keeps the pairs with the highest scores. The documents in these pairs make the document group. An agent reads the group and finds the connections in it.

Prediction markets with news

We used four dates between August 15 and October 1, 2026. On each date, each agent (GPT-5.6 Sol) got $10,000. The agent used the money to bet on open Polymarket questions. It kept each bet until the market settled. Each agent read 50 news articles that its method selected, or it searched about 1 GB of news itself. 75 agents ran on each date. On each date, we randomly select three start questions from different events. For each start question, the decision model scores the relationship between the question and 10,000 articles. It keeps the top 50 and gives them to the agent, which uses them to choose its bets (steps 3 to 6 above). Two hops keeps the top 25. Then it adds the top 5 of 500 new articles for each of the first five (step 7).

Each agent sees the full list of open markets. The agent searches the list and selects the questions for its bets. The decision model evaluates the articles against one randomly selected start question, but the agent can bet on all questions.

No information from after a decision date gets to an agent. We keep an article only if Common Crawl recorded it at least one hour before the decision time. The market rules come from archived copies from that time. The prices are the last prices before that time. The agents cannot use the web. They can use only the files that we give them. OpenAI released GPT-5.6 Sol in July 2026, and its knowledge stops in February 2026. Both dates are before the first decision date. Thus, the model did not know the results.

Mean return per agent:

On average, two hops made money (+8.9%). It was better than random on all four dates. Random lost 24.0%.

Stock trading with earnings calls

Each agent (GPT-5.6 Sol) read one excerpt from an earnings call and 60 more excerpts that its method selected. The filesystem agent searched all calls from the past year (about 30,000) itself. Each agent made a portfolio of 6 to 20 long or short positions. Each position has its own buy date and sell date, not later than October 16. We ran 60 agents for each method on four dates from August 1 to September 15, 2026. On each date, a model selected three start excerpts from 200 random excerpts. For each start excerpt, the decision model scores the relationship between the excerpt and 5,000 excerpts from the past year. It keeps the top 60 and gives them to the agent, which uses them to build its portfolio. The agent can trade any stock, not only the companies in the excerpts. Two hops keeps the top 30. Then it adds the top 3 of 500 new excerpts for each of the first ten.

All excerpts come from calls before the date. The agents have no other tools. OpenAI released GPT-5.6 Sol in July 2026, and its knowledge stops in February 2026. Both dates are before the first trading period. Thus, the model did not know the price changes. The dashed line shows the S&P 500 for the same periods.

Two hops had an annual return of +20.0% and a Sharpe ratio of 1.86. Three hops had +16.6% and 1.54. Both results are better than these results:

Picking proteins

A published study measured the brightness of 500 variants of green fluorescent protein (GFP). Each agent reads 30 papers that its method selects, or it searches all 3,486 papers about GFP itself. Then the agent selects the 10 variants that it thinks are the brightest. For our method, the start document is the task description. The decision model scores the relationship between the task and all 3,486 papers. It keeps the top 30 and gives them to the agent, which uses them to select its variants. Each method has 9 agents, so it makes 90 selections. Each square shows one selection. A filled square shows a variant in the true top ten of the 500.

Two hops had the most selections in the true top ten: 4 of 90. The filesystem agent had 2, and random papers had 1.

Connecting math papers

The method also works on openai/math. This set has 719 manuscripts that an OpenAI model wrote about open research problems. The three papers below are about C*-algebras, which describe quantum systems. A quasitrace gives each part of an algebra a size between 0 and 1. An algebra is properly infinite if it contains two separate copies of itself. The important line in the first paper is a theorem that it quotes only briefly. Thus, a search on the topic of the paper does not find it. We selected five start papers at random. For each start paper, the decision model scores the relationship between the paper and 5,000 passages. It keeps the top 100 and gives them to the agent, which looks for connections between any of them.

Writing GPU kernels

We used five KernelBench tasks. Each agent (GPT-6.1 Sol) gets one H100 GPU for one hour. It must write the fastest kernel that it can. The agent can use 33,192 notes about the work of earlier agents. The filesystem agent searches the notes itself with grep. Our method finds five stuck points, where the previous run stopped making progress. For each stuck point, the decision model scores the relationship between the stuck point and 5,000 notes, and it keeps the top 30. A summary agent reads these notes and writes a one-page summary. The next agent gets the summary and the notes, and it can use them in any way to write its kernel. After one round of notes, our agents wrote faster kernels than the filesystem agents on all five tasks.

The text below follows one task for three rounds: a decode kernel for the Kimi linear model.

Corpus: memory files generated from public agent traces

KernelBench publishes the full records of agents that work on its tasks. An LLM divided 823 of these records into parts. Each part stops when the agent gets a test or benchmark result. The LLM wrote one note for each part. The note tells what the agent tried, what it measured, and if the change stayed until the end. Each run also has a note about its final solution. In total, there are 33,192 notes, sorted by hardware, task and model. Nobody selected or edited them. They are only a set of files.

How the memory gets to the next agent

We compare two ways to give this memory to an agent: filesystem and our method. Each way runs as a loop. In round 0, three agents work with no memory. In rounds 1, 2 and 3, each method starts three new agents, one for each lineage. Each agent learns from the previous run in its lineage. We divide each completed run into notes and add them to the memory of that method. Round 0 goes into the memory of the two methods.

With filesystem, the next agent gets the full memory as files and searches it. Our method reads the notes for the agent. It takes a point from the previous run and reads each note against this point. It asks if the two together show a new idea. For kernels, we ask this exact question: would reading this note next to that moment suggest a concrete way to make the kernel faster, a useful direction to explore, or a way past the problem? Each run gives five points where the agent stopped making progress or found a limit. The method scores each point against 5,000 sampled notes and the notes from earlier rounds. Then a summary agent has ten minutes to write a one-page summary from the top 30 notes for each point.

Where the two fastest kernels came from

The two fastest kernels, 34.0× and 36.3×, use a method that the other 19 kernels do not use. Our method found both of them. The method is DP4A. This task keeps its weights as 4-bit integers. Most agents change the weights to bf16 before they multiply. DP4A does the opposite. It also changes the activations to 8-bit integers. Then it multiplies integers with __dp4a, a GPU instruction that does four 8-bit multiply-adds at one time. Thus, each weight needs less arithmetic. The precision decreases a little, but it stays in the tolerance of the benchmark.

The first kernel started from a point in round 0 where the agent stopped making progress. Our method did this with that point:

The summary agent put DP4A first in its summary: Prototype groupwise DP4A GEMVs early. The round-1 agent started on it after 8% of its hour. It got 34.0×, the best result at that time.

The second DP4A kernel came in round 3, from a different lineage. Its summary also started with DP4A. This time it used two different notes. One note is an H100 test of an int8 GEMV. The other note is a B200 run with a DP4A kernel. It also kept an exact bf16 path in case the accuracy decreased. That agent got 36.3×, the best kernel in the experiment.

The note for the first DP4A kernel was also in the filesystem memory. But none of the nine filesystem agents read it. There are two reasons: they searched for completed solutions, and the note does not look like a solution.

Personal memory

DynamicMem is a public benchmark. It gives the app log of a synthetic person: 2,637 entries from 16 apps over 15 months. Each square below shows one entry. Click an app to see its entries and an example.

The task is to plan one surprise for this person. The surprise must use a connection that no single entry shows. The two agents start from the same entry. In this entry, on a Monday night, the person makes images of glass and ice with software. We selected the start entry at random. The decision model scores the relationship between the start entry and 1,000 other entries. It keeps the top 30 and gives them to the agent, which uses them to plan the surprise. These entries make three groups. Each group shows one fact, and the three facts make one idea. Put the pointer on a dot or a box to read the entry.

The agent w/ filesystem and full corpus (Claude Opus 5.5) gets the full log as files. It searches the files with grep. The chart below shows the entries that each idea uses, across the year.

What's next

01
Scan the whole pile

Make pairs across a full corpus at one time. Are the best connections then more surprising?

02
Let agents choose

Most groups are not useful. Can an agent sort the groups and keep only the useful groups?

03
Better groups

Also score the pairs in each group, to find the groups with the strongest connections.

Forecasting. The Polymarket questions and rules come from the Wayback Machine. The news text comes from CC-NEWS, and all methods use the same fixed set. On each date, the set includes 48–76% of the open markets. The agents use GPT-5.6 Sol (high). The OpenAI Decisions API (gpt-6-luna) scores the pairs. We have 299 portfolios, because one agent of the random method failed. The returns use the last price before the decision time, with no fees.

Trading. We have 300 portfolios. The fills use the daily average price, with no costs. 43 of 3,226 positions had no price, and they count as zero. The annual return is the return of each portfolio multiplied by 252 and divided by the number of trading days. The Sharpe ratio uses daily returns with no risk-free rate, and we show the mean across agents. The S&P 500 line is $10,000 of SPY, scored with the same code for the same periods. The transcripts are October 2026 downloads, and they can be different from the versions at that time.

Proteins. The data is the ProteinGym GFP assay, with a fixed set of 500 variants.

News pages. We took the screenshots of the articles on October 26, 2026 from the live pages, and they link to these pages. The agents read the CC-NEWS text of these articles.

Personal memory. The data is DynamicMem user 002, a synthetic person (MIT license).
